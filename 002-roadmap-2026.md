# Cruise Control Roadmap (2026)

This proposal outlines the development priorities for Cruise Control following the first release (`3.1.0`) under the Linux Foundation.
The focus is on reducing technical debt and improving long-term maintainability now that the immediate CVE exposure has been resolved.

## Current situation

The first Cruise Control release under the Linux Foundation (3.1.0) has been shipped.
This release addressed outstanding CVEs, stabilized CI, and cleaned up some of the Gradle build configuration.
The details of that release are documented in [001-first-release.md](001-first-release.md).

Cruise Control artifacts are now published to the `io.cruise-control` namespace of Maven Central under the Linux Foundation.
Older artifacts from prior releases remain on LinkedIn's JFrog repository and work is in progress with LinkedIn to publish those to Maven Central with relocation metadata pointing consumers to the new namespace.

With the immediate CVE exposure resolved and the release process validated, the project can now turn its attention to longer-term improvements.
The codebase still carries significant technical debt, including dependencies on internal Kafka APIs, stale features, and a large backlog of untriaged issues and pull requests.

## Motivation

Publishing this roadmap provides visibility into the project's direction, helps contributors prioritize their efforts, and invites community input on the ordering and scope of future work.

## Proposal

- **Introduce an issue triage workflow**: Define and document a triage workflow for the project, then apply it to the existing backlog of issues and pull requests. 
 This includes evaluating current labels, defining new ones, establishing prioritization criteria, and identifying what is still relevant, actionable, or ready to close.

- **Migrate off internal Kafka APIs**: Replace dependencies on private Kafka APIs with supported public APIs to reduce upgrade friction across Kafka releases.
 The existing issue should be reopened since the migration is not yet complete.
 This work has already started and is being tracked [here](https://github.com/cruise-control-for-kafka/cruise-control/issues/2282).

- **Deprecate stale features**: Review the existing feature set and identify features that are no longer used, relevant, or maintained, then plan their deprecation or removal.

- **Clean up Gradle dependency management**: Audit and streamline Gradle build scripts by removing unused dependencies, resolving version inconsistencies and simplifying dependency declarations.
 The first release addressed the most critical issues, but significant cleanup remains.

- **Introduce automated dependency management**: Evaluate and adopt Dependabot or Renovate to automate dependency update detection and improve visibility into security fixes.

- **Test against multiple Kafka versions**: Update the test suite to run against multiple Kafka versions to improve compatibility coverage and detect version-specific issues earlier.

- **Fix Vert.x webserver implementation**: Investigate and repair the Vert.x webserver implementation which appears to be broken and may no longer be in active use.
 If it is determined to not be used or needed, deprecate it and plan for its removal from the codebase.

- **Java package rename**: Migrate from the legacy `com.linkedin.cruisecontrol` package namespace to `io.cruisecontrol` now that the project operates under the Linux Foundation and is no longer maintained by LinkedIn.

## Affected/not affected projects

### Affected projects

The Cruise Control repository is the target of all roadmap items.

## Compatibility

Most of these items focus on internal changes that should not affect user-facing behavior.
Of course, the Java package rename is an exception for downstream consumers who rely on the `com.linkedin.cruisecontrol` package namespace.
